# Security policy

## Reporting a vulnerability

Please **do not open a public issue** for a security problem. Use GitHub's private
reporting instead:

> [Report a vulnerability](https://github.com/rwijnen/folio-viewer/security/advisories/new)

That opens a private advisory visible only to you and the maintainer. If you would
rather not use GitHub, the maintainer's contact address is on his
[GitHub profile](https://github.com/rwijnen).

Expect an acknowledgement within a week. This is a spare-time project with one
maintainer, so please be patient with fixes — and say if you intend to disclose
publicly on a schedule, so it can be met.

## What Folio is exposed to

Folio opens files that arrive from elsewhere: a patch from a colleague, a Markdown
report generated by a tool, a document downloaded from the internet. The threat model
is therefore **hostile file contents**, and the app is built around three rules:

1. **It writes only on request, only to the file you are editing.** Diffs are never
   written — the patch is applied in memory and has no save path. A Markdown document you
   have opened can be edited and saved back to itself with ⌘S. Nothing is auto-saved,
   nothing is written on quit without asking, saving goes through a temporary file so an
   interrupted write cannot truncate your document, and no content of a document can
   cause a write on its own.
2. **It never uses the network.** Not at build time (mermaid is vendored), not at run
   time. The rendered page runs under a `Content-Security-Policy` of
   `default-src 'none'; connect-src 'none'`, with images restricted to `data:` URIs
   that the converter inlined itself.
3. **It does not execute what it renders.** Raw HTML in Markdown is escaped except for a
   whitelist of attribute-free formatting tags, `javascript:` and similar URL schemes are
   stripped from links, and the only script that can run in the page is the bundled
   mermaid bootstrap, admitted by a per-load nonce.

Findings that would be especially valuable:

- Markdown, or a diff, that gets script to run in the rendered page.
- A path in a diff that makes Folio read a file outside the folder you chose.
- Anything that makes the app write to a file other than the Markdown document being
  edited, or write without the reader asking.
- Content that makes the app reach the network.
- A crash reachable from a malformed diff or document (denial of service is minor for a
  viewer, but crashes often hide worse).

## Known, accepted limitations

- **Release builds are ad-hoc signed, not notarised.** There is no paid Apple Developer
  certificate behind this project, so downloaded builds carry no verifiable publisher
  identity. If that matters to you, build from source — see [INSTALL.md](INSTALL.md).
- **The app is not sandboxed.** It needs to read arbitrary files you point it at,
  including the originals referenced from a diff.
- **The code was written by an AI and has not been independently audited.** Folio was
  vibecoded in Claude Code; see [How this was built](README.md#how-this-was-built). The
  rules above are covered by tests, but tests only cover what someone thought to check,
  and no third party has reviewed this. Treat a finding here as more likely, not less.
- **mermaid is a large third-party dependency** (3.4 MB of JavaScript) running inside the
  page. It is confined by the CSP above and cannot reach the network, but it is the
  biggest piece of code in the project that was not written for it. See
  [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md).

## Supported versions

The latest release and `main` are supported. There are no long-term support branches.
